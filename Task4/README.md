## Стратегия

Используется **инкрементальная миграция по доменам и продуктовым волнам**:

1. сначала обнаружить данные, зависимости и владельцев
2. затем создать общие ID, справочники, интеграционный и аналитический фундамент
3. перевести чтение и отчётность на новые data products
4. мигрировать операционные продукты только после trial migration и двойной сверки
5. выводить legacy отдельно по каждому модулю после доказанного отсутствия consumers

Big-bang и длительная двусторонняя запись запрещены. В конкретный момент одна финансовая запись имеет один `servicing_system` и одну мастер-систему

## Ограничение горизонта

За 12 месяцев реалистично гарантировать отключение RB DWH/BI, большей части point-to-point и мигрированных модулей CRM/продуктовых систем. Отключение RB Core/Cards/Loans не назначается только по календарю: оно выполняется по продуктовой волне при прохождении финансовых, юридических и операционных exit gates. Остаточный модуль переводится в read-only с владельцем и утверждённой датой выхода, если gate не пройден

Это не ослабление целевого состояния: условный вывод безопаснее фиктивного `успеха`, после которого legacy продолжает скрыто обслуживать продукты

## Принципы миграции

- клиентские сервисы остаются доступными; freeze ограничивается конфигурацией/справочниками и короткими объектными окнами
- snapshot + CDC catch-up вместо остановки систем на время полной выгрузки
- сначала shadow/dual read и сверка, затем переключение маршрута
- dual write допускается только как короткий контролируемый механизм с reconciliation и owner
- исходные идентификаторы, business time, load time и lineage сохраняются
- проведённые операции не переписываются — корректируются новой записью
- каждый этап имеет entry/exit criteria, rollback point и business sign-off
- legacy выключается только после инвентаризации consumers, retention/legal hold и проверенного восстановления архива

## Определение завершённости

Миграция считается завершённой не после копирования таблиц, а когда:

- целевые мастера принимают все новые записи выбранного scope
- consumers переключены и зарегистрированы в DataHub
- финансовая и бизнес-сверка пройдена
- target SLO выдержан в период hypercare
- fallback window закрыто решением Go/No-Go board
- legacy write закрыт, доступ ограничен read-only архивом либо система выведена
- CMDB, схемы, lineage, runbooks, ownership и retention обновлены
